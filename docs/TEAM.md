These are responsibilities, not an assumed five-person roster. Combine or rotate roles based on team size. Every member should contribute implementation and review evidence appropriate to course requirements.

## Routine
- Weekly planning: select achievable items and identify dependencies.
- Short progress updates: completed work, next task and blocker.
- Weekly integration demo: run the application from main.
- Record consequential decisions and action owners in meeting notes.
- Escalate a blocker after one working day; pair with another member.

## GitHub board proposal
Backlog → Ready → In progress → Review → Done.
Use labels such as frontend, backend, decision-engine, docs, test, bug, P0 and P1.
Each issue needs an owner, reviewer, acceptance criteria and dependency links.
Board, labels and repository protection are proposed; this documentation does not create them.
